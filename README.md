# Adashboard (Another Dashboard)

Ещё один Дашборд. Настраиваемая стартовая страница для личного использования. Максимально простая и понятная в использовании и настройке.

## Возможности

- несколько настраиваемых страниц, у каждой — свой набор категорий и карточек;
- карточки-ссылки с иконками (встроенные - Font Awesome или загруженное изображение), цветом фона и размером;
- индикатор состояния сервиса (health-check);
- настройки оформления: тема, интервал проверки состояния, боковое меню;
- защита ключом доступа;
- хранение данных в SQLite — внешних зависимостей (отдельной базы, кэша) не требуется.

## Запуск в Docker

Приложение запускается контейнером.

Пример `docker-compose.yml`:

```yaml
services:
  adashboard:
    build: .
    image: adashboard:latest
    container_name: adashboard
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      # Пустое значение отключает защиту приложения. Задайте свой ключ, чтобы включить её.
      ApiKey: ""
      # Уровень логирования: Trace, Debug, Information, Warning, Error, Critical, None.
      LogLevel: Information
    volumes:
      - data:/app/appdata

volumes:
  data:
```

Запуск:

```bash
docker compose up -d --build
```

Приложение доступно на `http://localhost:8080`, проверка API — на `http://localhost:8080/api/health`.

Остановка:

```bash
docker compose down
```

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ApiKey` | пусто | ключ доступа к API; пустое значение отключает защиту |
| `LogLevel` | `Information` | уровень логирования по умолчанию; отдельные категории из `appsettings.json` сохраняют свои уровни |
| `ASPNETCORE_URLS` | `http://+:8080` | адрес, на котором слушает сервер внутри контейнера |


## Данные

Всё изменяемое лежит в каталоге `/app/appdata` (в примере — volume `adashboard-data`):

- `data.db` — база SQLite;
- `uploads` — загруженные изображения и стандартные ассеты.
- `uploads/assets` — фоны приложения для тёмной и светлой темы и иконка приложения. Могут быть заменены на свои.
