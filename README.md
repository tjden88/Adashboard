# Adashboard

Настраиваемая стартовая страница для личного использования, по концепции похожая на Dashy или Homarr.

## Возможности

- несколько страниц dashboard, у каждой — свой набор категорий и карточек;
- карточки-ссылки с иконками (Font Awesome или загруженное изображение), цветом фона и размером;
- индикатор состояния сервиса (health-check) и заголовок целевой страницы;
- настройки оформления: тема, интервал проверки состояния, вид бокового меню;
- защита API ключом доступа;
- хранение данных в SQLite — внешних зависимостей (отдельной базы, кэша) не требуется.

## Запуск в Docker

Приложение запускается контейнером. Каталог данных подключается volume, поэтому база,
загруженные иконки и настройки переживают пересоздание контейнера.

Пример `docker-compose.yml`:

```yaml
services:
  adashboard:
    build: .
    image: adashboard:latest
    container_name: adashboard
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      # Пустое значение отключает защиту API. Задайте свой ключ, чтобы включить её.
      ApiKey: ""
      # Уровень логирования: Trace, Debug, Information, Warning, Error, Critical, None.
      LogLevel: Information
    volumes:
      - adashboard-data:/app/appdata

volumes:
  adashboard-data:
```

Запуск:

```bash
docker compose up -d --build
```

Dashboard доступен на `http://localhost:8080`, проверка API — на `http://localhost:8080/api/health`.

Просмотр логов и остановка:

```bash
docker logs -f adashboard
docker compose down
```

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ApiKey` | пусто | ключ доступа к API; пустое значение отключает защиту |
| `LogLevel` | `Information` | уровень логирования по умолчанию; отдельные категории из `appsettings.json` сохраняют свои уровни |
| `ASPNETCORE_URLS` | `http://+:8080` | адрес, на котором слушает сервер внутри контейнера |

### Ключ доступа

При заданном `ApiKey` каждый запрос к API должен приходить с заголовком `X-Api-Key`, иначе сервер
отвечает `401`. Клиент в этом случае показывает экран ввода ключа; ключ хранится в браузере.
Статика клиента и пользовательские загрузки остаются открытыми — без них dashboard не загрузился бы.

Не храните секрет в репозитории: задавайте `ApiKey` через переменную окружения или `.env`,
который не попадает в Git.

## Данные

Всё изменяемое лежит в каталоге `/app/appdata` (в примере — volume `adashboard-data`):

- `data.db` — база SQLite;
- `uploads` — загруженные изображения и стандартные ассеты.

Миграции и стартовое наполнение применяются автоматически при запуске. Не удаляйте volume без
необходимости: `docker compose down -v` вместе с ним удалит базу и загрузки.
