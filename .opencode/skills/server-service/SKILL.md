# Сервисы сервера

## Результаты операций

- Сервис возвращает `OperationResult` или `OperationResult<T>` из библиотеки `WPR.Operations`;
  контроллер переводит результат в HTTP-ответ.
- Фабрики: `Result.Success()`, `Result.Failure("...")`, `Result.Failure<T>("...")`,
  `Result.Failure("...").As<T>()` для результата без значения со «своим» типом.
- Ошибка — строка с текстом для пользователя. Исключения только для неожиданных сбоев:
  «не найдено», «некорректные данные», «путь занят», «основную страницу удалить нельзя» — это результат, не исключение.
- Свой тип ошибки не заводим; если код ответа зависит от причины — `OperationResult<T, HttpStatusCode>`
  (или `<T, int>`) из той же библиотеки.

## Логирование

- `ILogger` из ASP.NET, сообщения на русском, структурированные параметры (`{Name}`), не конкатенация.
- Уровень: `LogInformation` — только результат изменяющей операции; `LogDebug` — чтение, начало операции,
  служебные действия; `LogWarning` — нетипичные, но ожидаемые сценарии; `LogError` — неожиданные ошибки.
- Минимум для публичной операции: `LogDebug` в начале, `LogInformation` в конце (для чтения — `LogDebug`),
  `LogWarning` для отказа.
- В логи не писать секреты, токены, пароли, cookies, connection string, полные payload.

## Комментарии

Только `/// <summary>…</summary>`: у класса, у всех публичных методов, у публичных свойств, если назначение
неочевидно. Приватные методы — если без комментария непонятна цель. Комментарии к тривиальным геттерам не нужны.

## Прочее

- Маппинг «сущность ↔ контрактная модель» — Mapster, глобальный конфиг `MapperConfig`, без кодогенерации.
- DI-регистрации смотрим в `Adashboard.Server/Program.cs`; сервисы внедряются как реализации.
- Общие ограничения и значения по умолчанию — `Adashboard.Domain.Reference.DomainConstants`.
- Внешние запросы: `IHttpClientFactory`, таймауты, отмена, `AllowAutoRedirect = false` там, где важен
  настоящий код ответа (`ProbeService`), понятный `User-Agent`.
