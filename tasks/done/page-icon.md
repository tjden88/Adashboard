# Иконка страницы dashboard

## Цель
Добавить страницам dashboard собственную встроенную иконку Font Awesome, чтобы страницу можно было узнавать по оформлению шапки. Иконка выбирается в диалоге страницы так же, как встроенная иконка карточки; кастомные изображения для страниц не поддерживаются.

## Требования
- В контрактную модель `DashboardPage` добавить строковое свойство `Icon` — CSS-класс иконки Font Awesome (например, `fa-solid fa-file`). В `DomainConstants` добавить константу максимальной длины класса иконки и использовать её в атрибутах контракта и сущности.
- В сущность БД `DashboardPageEntity` добавить столбец `Icon` с ограничением длины; создать и применить миграцию EF Core. Существующие страницы получают пустую строку.
- Маппинг «сущность ↔ контракт» оставить на Mapster (`MapperConfig` / `Adapt`), отдельного кода для `Icon` не писать, если он не нужен.
- Иконка необязательна: пустая строка означает «без иконки», подстановку иконки по умолчанию не делать.
- В `PageDialog` добавить поле «Иконка»: для выбора использовать существующий общий компонент `IconPicker` (как встроенная иконка в `CardDialog`), с подписью для скринридеров. Режим «своё изображение», загрузка файла и вставка из буфера для страниц не нужны.
- В диалоге должна быть возможность очистить иконку (сбросить в пустое значение), чтобы вернуть страницу к варианту «без иконки».
- Значение `Icon` сохранять вместе с остальными полями страницы: `POST /api/pages` и `PUT /api/pages/info` должны принимать и возвращать его без изменений клиентского Refit-интерфейса.
- В шапке (`Header.razor`) отображать иконку текущей страницы перед заголовком, только если `Icon` не пустая. На время загрузки страницы иконка не рисуется (вместе со скелетом заголовка и описания).
- Добавить стили иконки в `Header.razor.css`: размер согласован с заголовком, корректная работа на мобильной ширине и в светлой/тёмной теме.
- Кастомные изображения-иконки страниц не поддерживаем: никаких файлов, путей и флагов `IsCustomIcon` для страниц.
- Комментарии в коде — по правилам проекта (только `summary`, на русском).

## Критерии приёмки
- [ ] `DashboardPage` и `DashboardPageEntity` содержат `Icon`, миграция создана и применена, существующие страницы открываются без ошибок.
- [ ] В диалоге создания и редактирования страницы можно выбрать встроенную иконку через `IconPicker` и очистить её.
- [ ] Выбранная иконка сохраняется на сервере и показывается перед заголовком в шапке после перезагрузки страницы.
- [ ] При пустой иконке шапка выглядит как раньше, без пустого места и битой вёрстки.
- [ ] После изменения API выполнены две сборки (обновление OpenAPI и пересборка клиента), проект собирается без ошибок.
