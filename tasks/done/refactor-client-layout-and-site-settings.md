# Рефакторинг клиента: компонент заголовка, настройки сайта и контрактные модели

## Цель

Привести клиент `Adashboard.Client` в порядок и вернуть работу с настройками сайта:

- применять настройки сайта (`SiteSettings`: тема, показ логотипа, интервал проверки статуса) при загрузке
  и снова дать их редактировать (отдельная кнопка и диалог настроек сайта);
- разгрузить компоненты: использовать контрактные модели и вложенные `EditModel` вместо множества
  отдельных приватных полей;
- перенести логику из родительских компонентов в дочерние там, где это уменьшает связи и дублирование;
- выделить компонент заголовка, который владеет настройками и переключает режим редактирования.

Меняем только клиент. Сервер, `Adashboard.Domain` и `Adashboard.Data` не трогаем: эндпоинты настроек
(`GET`/`PUT /api/settings`, `SiteSettings`, `SiteSettingsService`) уже существуют. Поведение сохраняем 1:1,
кроме новой функциональности настроек сайта.

## Требования

### Настройки сайта

- Добавить клиентский сервис-владелец настроек (например, `SiteSettingsService` в `Adashboard.Client/Services`),
  зарегистрированный в `Program.cs`. Сервис:
  - загружает настройки через `IDashboardApi.GetSettingsAsync` (контракт `SiteSettings`) и сохраняет через `SaveSettingsAsync`;
  - хранит текущий экземпляр `SiteSettings`, отдаёт его компонентам и публикует событие изменения (`OnChange`);
  - логирует операции через `ILogger` по правилам проекта (чтение — `LogDebug`, сохранение — `LogInformation`,
    нетипичные сценарии — `LogWarning`), сообщения на русском со структурированными параметрами.
- Новый компонент заголовка (например, `LayoutHeader`) владеет настройками: содержит логотип, заголовок и описание
  текущей раскладки, кнопку переключения режима редактирования и кнопки открытия настроек. Переключение режима
  редактирования переносится в него из `LayoutView` (сам `EditModeService` остаётся общим).
- В шапке в режиме редактирования добавить отдельную кнопку настроек сайта, открывающую отдельный диалог
  (например, `SiteSettingsDialog`). Диалог редактирует `ThemeMode`, `ShowLogo`, `HealthCheckIntervalSeconds`
  и сохраняет их через `PUT /api/settings`.
- Существующий `SettingsDialog` (кнопка-шестерёнка) продолжает отвечать только за заголовок и описание раскладки.

### Применение настроек

- Настройки применяются при загрузке без перезагрузки страницы и обновляются сразу после сохранения:
  - тема — через JS-модуль (`setThemeMode`; `initializeTheme` использовать для стартового значения);
  - показ логотипа — по `SiteSettings.ShowLogo` в шапке;
  - интервал проверки статуса — `Card` берёт его из настроек вместо константы `HealthCheckIntervalSeconds`,
    изменение интервала вступает в силу без перезагрузки (цикл проверок учитывает новое значение).
- Убрать кратковременное мигание темы при загрузке: сохранять последнюю применённую тему в `localStorage`
  и применять её inline-скриптом в `wwwroot/index.html` до отрисовки; после загрузки настроек с сервера
  значение уточняется.

### Компоненты и структура

- Переименовать `DashboardView` → `LayoutView` (файл, имя компонента, класс, ссылки в `Home.razor`,
  комментарии и XML). Имя `Layout` не использовать из-за путаницы с `MainLayout`/`LayoutComponentBase`.
  `LayoutView` отвечает за загрузку раскладки, шапку (через `LayoutHeader`), сетку категорий, drag-and-drop
  и изменение ширины категорий.
- Перенести CRUD категории (создание/изменение/удаление: открытие диалогов и вызовы API) из `LayoutView`
  в компонент `Category`; родителю сообщать о результате событиями (например, `CategorySaved`/`CategoryDeleted`),
  чтобы общий список категорий оставался актуальным.
- Заменить множество приватных полей в диалогах на вложенный приватный `EditModel`:
  - `CardDialog` → `CardEditModel`;
  - `CategoryDialog` → `CategoryEditModel`;
  - `SettingsDialog` → `EditModel` (заголовок/описание) ;
  - `SiteSettingsDialog` → `EditModel`.
- В компонентах использовать контрактные модели (`DashboardCard`, `DashboardCategory`, `SiteSettings`)
  как основной носитель данных; `EditModel` держит редактируемые поля и умеет отдавать/принимать контрактную модель.
- По мере рефакторинга убирать дублирование обработки ошибок и лишние параметры/события между родителем и потомками.

### Общие ограничения

- Правки — только в `Adashboard.Client`. `Adashboard.Server`, `Adashboard.Domain`, `Adashboard.Data` не меняем.
- Формат сохраняемых данных и существующее визуальное поведение не меняем.
- Комментарии и сообщения логов — на русском; для сервисов обязательны XML-комментарии; nullable reference types соблюдаем.

## Критерии приёмки

- [ ] Решение (в первую очередь `Adashboard.Client`) собирается без ошибок.
- [ ] Настройки сайта загружаются через `GET /api/settings` и применяются при загрузке: тема, показ логотипа, интервал проверки.
- [ ] В шапке в режиме редактирования есть отдельная кнопка настроек сайта; диалог сохраняет изменения через `PUT /api/settings`, и они применяются сразу, без перезагрузки.
- [ ] При загрузке тема применяется без мигания (значение хранится в `localStorage` и применяется inline-скриптом до отрисовки).
- [ ] Интервал проверки статуса берётся из настроек сайта; изменение интервала применяется без перезагрузки.
- [ ] `DashboardView` переименован в `LayoutView`; ссылки и комментарии обновлены.
- [ ] CRUD категории выполняется внутри `Category`; `LayoutView` не содержит вызовов API категорий, а получает результат событиями.
- [ ] Диалоги используют вложенные `EditModel` вместо набора отдельных приватных полей.
- [ ] Все комментарии и логи — на русском; логирование сервиса настроек соответствует правилам проекта.
