# Перенос фронтенда старого Blazor-приложения на SvelteKit

## Цель
Перенести пользовательский интерфейс dashboard из старого Blazor-проекта `Adashboard` в SvelteKit-проект `Adashboard.Web`, сохранив функциональность: сетку категорий и карточек, перетаскивание, режим редактирования, диалоги, темы и индикаторы статуса. Оформление переписывается на Tailwind, поэтому небольшое визуальное отличие от старого дизайна допустимо. Связь с backend API на этом этапе не делается.

## Требования
- **Рабочая область:** всё делается в `Adashboard.Web` (SvelteKit, TypeScript, adapter-node, npm). Проект `Adashboard` (Blazor) не изменяется и не удаляется.
- **Без API:** связь с `Adashboard.Api` не делается. Сетевые обращения возможны только из браузера — health-check и получение заголовка страницы.
- **Только память:** раскладка хранится в памяти и при перезагрузке страницы сбрасывается к стартовым данным. Персистентность (localStorage, файлы, API) не добавляется.
- **Стартовые данные:** те же, что в `DebugDbInitializer` Blazor-проекта — 3 категории (Networking & Management, Mediaserver, Services) с карточками, цветами, иконками и флагами «широкая».
- **Стек и библиотеки:** Tailwind CSS вместо Bootstrap и старого `app.css`; перетаскивание — `svelte-dnd-action`; раскладка категорий — `gridstack.js` (12 колонок, ширина категории 1–12, только размещение, drag/resize у gridstack отключены); диалоги — нативный `<dialog>`; выбор цвета — готовый Svelte-компонент; иконки — Font Awesome; вставка изображения из буфера — через событие `paste` средствами Svelte.
- **Font Awesome:** перенести ассеты (CSS + webfonts) и справочник иконок (список `FontAwesomeIcons` конвертировать в TS-модуль), сохранить поиск иконок в диалоге карточки.
- **Модель данных (TS):** `DashboardLayout`, `DashboardCategory`, `DashboardCard`, режим проверки `None/Reachable/NoServerError/Success`, состояние `Unknown/Online/Offline`; поля как в Blazor (id, title, url, urlScheme, iconClass, imagePath/dataUrl, backgroundColor, isWide, statusMode, order, width, тема и настройки сайта).
- **Цвет иконки/текста:** перенести автоматический подбор светлых/тёмных текста и иконки по яркости фона (аналог `ShouldUseLightText`).
- **Цвет фона по умолчанию:** перенести подбор по ключевому слову иконки (database → #b91c1c, chart → #ea580c, docker → #0369a1, heart → #15803d, иначе → #1e40af).
- **Шапка:** логотип (если включён), заголовок, описание, кнопка переключения режима редактирования; в режиме редактирования — кнопки «добавить категорию» и «настройки».
- **Сетка категорий:** заголовок, drag-handle и действия (добавить карточку, редактировать, удалить) видны только в режиме редактирования; ширина категории берётся из настроек.
- **Карточки:** переход по ссылке в новой вкладке, иконка Font Awesome или своё изображение, подпись, цвет фона, признак «широкая» (2 колонки), индикатор статуса; в режиме редактирования клик открывает диалог редактирования, а не ссылку; адаптивность по desktop/medium/mobile как в Blazor.
- **Перетаскивание:** переупорядочивание категорий и карточек и перенос карточек между категориями; доступно только в режиме редактирования.
- **Диалоги:** настройки (тема auto/dark/light, заголовок, описание, показывать логотип, интервал проверки 10–600 с); категория (название, ширина 1–12); карточка (заголовок, URL с циклическим переключением схемы http/https/без схемы, FA-иконка или своё изображение, цвет фона, «широкая», режим проверки статуса, кнопка получения заголовка страницы, удаление); подтверждение удаления (закрытие по Escape и по клику на оверлей).
- **Тема:** auto/dark/light через атрибут `data-theme` на `html` и Tailwind dark mode; при auto учитывать системную тему и её изменение.
- **Health-check:** периодические проверки из браузера с ограничением числа одновременных запросов; семантика режимов как в `HealthCheckService` (Reachable — любой ответ; NoServerError — код < 500; Success — 2xx); интервал из настроек; немедленная проверка после добавления/правки карточки; коды ошибок/CORS дают offline или unknown, интерфейс не ломается.
- **Получение заголовка:** браузерный fetch и разбор `<title>`, обрезка и нормализация пробелов, понятные сообщения об ошибках (включая CORS и таймаут).
- **Своя иконка:** поддерживать изображение по URL и вставку из буфера (data URL); загрузку файла с устройства в этой задаче не делать.
- **Ассеты:** перенести в `Adashboard.Web/static` фоны light-bg.jpg/dark-bg.jpg, logo.png, набор favicon и site.webmanifest, ассеты Font Awesome. Bootstrap, Coloris и старые JS-скрипты не переносить.
- **Доступность:** семантический HTML, клавиатурная навигация, заметный focus, ARIA-подписи; диалоги с role="dialog" и aria-modal.
- **Комментарии:** на русском языке, с обучающим уклоном по Svelte/SvelteKit (см. AGENTS.md, раздел «Обучение SvelteKit»).
- **Регресс:** не менять файлы проекта `Adashboard`; решение `Adashboard.slnx` должно по-прежнему собираться.

- [x] Сетка 12-колоночная, ширина категорий учитывается, «широкие» карточки занимают две колонки, раскладка адаптивна на desktop/tablet/mobile.

- [x] Диалоги настроек, категории, карточки и подтверждения работают на нативном `<dialog>`; настройки применяются к отображению.

- [x] Индикаторы статуса показывают unknown/online/offline по результатам браузерных проверок согласно выбранному режиму.

- [x] Изображение-иконку карточки можно задать по URL и вставкой из буфера; оно отображается на карточке.
- [x] Проект `Adashboard` не изменён, а `dotnet build Adashboard.slnx` по-прежнему проходит.

## Отклонение от ТЗ
Перетаскивание реализовано на нативном HTML5 Drag and Drop, а не на `svelte-dnd-action`: библиотека нестабильно работает с абсолютной раскладкой gridstack и теряла/дублировала перетаскиваемые элементы. Отклонение согласовано с пользователем; пакет `svelte-dnd-action` удалён из зависимостей.
