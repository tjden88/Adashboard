# Несколько страниц dashboard и переименование «Раскладка» → «Страница»

## Цель

Добавить поддержку нескольких страниц dashboard. Сейчас «раскладка» — по сути единственная страница
(шапка + сетка категорий с карточками). Нужно, чтобы таких страниц было много, каждая доступна по своему
относительному пути, а категории можно было распределять по страницам. Заодно переименовать понятие
«Раскладка» в «Страница» во всех слоях — от контрактных моделей и схемы БД до UI, логов и комментариев —
чтобы название отражало фактическую суть.

Основная страница имеет пустой путь и удалить её нельзя. Пользовательские страницы создаются и удаляются
из UI, их путь — относительный сегмент адреса.

## Требования

**Терминология.** Полное переименование «Раскладка» → «Страница», русские тексты и английские имена:
- `Adashboard.Domain`: `DashboardLayout` → `DashboardPage`, `DashboardLayoutReadModel` → `DashboardPageReadModel`
  (свойство `Layout` → `Page`), `DashboardCategory.DashboardLayoutId` → `DashboardPageId`.
- `Adashboard.Data`: `DashboardLayoutEntity` → `DashboardPageEntity`, `DashboardDb.Layouts` → `Pages`,
  внешний ключ/навигации `DashboardLayoutId`/`Layout` → `DashboardPageId`/`Page`.
- `Adashboard.Server`: `LayoutService` → `PageService`, `LayoutController` → `PageController`, все логи и XML-комментарии.
- `Adashboard.Client`: `LayoutView.razor` → `PageView.razor`, `LayoutHeader.razor` → `PageHeader.razor`
  (вместе с `.razor.css`), `SettingsDialog` → `PageDialog`, комментарии и вызовы API.
- Каркасные Blazor-понятия не трогаем: `LayoutComponentBase`, `DefaultLayout`, `MainLayout`, `DialogContainer` —
  это «разметка», а не доменная «раскладка».

**Модель страницы.** В `DashboardPage` (и одноимённой сущности) добавить свойство `Path` — относительный путь,
по которому страница доступна. У основной страницы путь пустой; у пользовательских — непустой.
Правила пути: латиница в нижнем регистре, цифры и дефис (`^[a-z0-9]+(?:-[a-z0-9]+)*$`), не начинается и не
заканчивается дефисом, максимум 120 символов, уникален среди страниц. Валидация — и на клиенте, и на сервере
(на сервере путь авторитетный: занятый путь отклоняется).

**Схема БД и миграция.** Старые миграции и БД удалены. После правок моделей создать новую единую init-миграцию.
`DashboardPageEntity.Path` — обязательное поле с уникальным индексом. `DbInitializer` для основной страницы
проставляет пустой `Path`; прочие стартовые данные не меняются. Миграцию применяет `DbInitializer` при старте.

**API (сервер).** `PageController` на маршруте `api/pages` (бывший `LayoutController` / `api/layout`):
- `GET /api/pages` (`Name = "GetPages"`) → `IReadOnlyList<DashboardPage>` — список всех страниц (нужен для селектора категории).
- `GET /api/pages/{id:int}` (`Name = "GetPage"`) → `DashboardPageReadModel` — страница с категориями и карточками.
- `POST /api/pages` (`Name = "CreatePage"`) → созданная `DashboardPage`; отклоняет пустой/занятый/некорректный путь.
- `PUT /api/pages/info` (`Name = "SavePageInfo"`) → изменение `Title`, `Description`, `Path`; проверка уникальности пути.
- `DELETE /api/pages/{id:int}` (`Name = "DeletePage"`) → удаление страницы с категориями и карточками; для основной
  страницы (пустой путь) возвращает ошибку и не удаляет её.
- Старый `LayoutController` и маршруты `/api/layout*` убрать. `CategoriesController`/`CardsController` сохраняют
  маршруты, но работают с `DashboardPageId`.

**Сервис (сервер).** `PageService` (бывший `LayoutService`) получает методы: список страниц, чтение страницы по id,
создание страницы (с проверкой пути и генерацией/нормализацией пути при необходимости), изменение информационной
части и пути, удаление страницы (с проверкой, что это не основная страница, каскадом категорий/карточек и удалением
файлов кастомных иконок). CRUD категорий и карточек сохраняется. Логирование по общим правилам проекта: `LogDebug`
на чтение и начало, `LogInformation` на результат изменения, `LogWarning` на «не найдено / отклонено / путь занят».

**Маршрутизация клиента.** Один компонент-страница получает два маршрута: `@page "/"` и `@page "/{PagePath}"`.
Компонент по сегменту пути находит страницу в списке `GetPages`, загружает её read-модель и рисует шапку и сетку.
Если путь не найден — понятное сообщение об ошибке и переход/ссылка на основную страницу. Переход между страницами
осуществляется по прямому URL; отдельное меню навигации в задачу не входит.

**Шапка (`PageHeader`).** Добавить кнопку «Добавить страницу» рядом с кнопкой редактирования; показывать её только
в режиме редактирования. Кнопку «Настройки сайта» оставить в шапке. Кнопки «Добавить категорию» и «Настройки
страницы» из шапки убрать.

**Действия на странице (`PageView`).** Отдельным блоком (между шапкой и сеткой, видимым в режиме редактирования)
разместить кнопки с текстом внутри: «Добавить категорию», «Настройки страницы», «Удалить страницу». Кнопку удаления
не показывать/не давать нажать для основной страницы (пустой путь).

**Диалог страницы (`PageDialog`).** Бывший `SettingsDialog` с полями «Название», «Описание», «Путь». Используется
и для создания, и для редактирования. При создании путь пустой: пока пользователь не трогал поле пути, slug
генерируется из названия (транслитерация кириллицы в латиницу, пробелы и спецсимволы → дефис, нижний регистр).
Как только путь введён/изменён вручную или открыт режим редактирования существующей страницы — автогенерация
отключается. Перед сохранением — валидация пути и понятное сообщение при ошибке; на клиенте показывается занятый путь.

**Диалог категории (`CategoryDialog`).** Добавить селектор страницы: выпадающий список всех страниц. При создании
предвыбрана текущая страница, при редактировании — страница категории. При сохранении категория уходит в выбранную
страницу (`DashboardPageId`). Если категорию перенесли на другую страницу, текущий список категорий обновляется
(категория исчезает с текущей страницы).

**Удаление страницы.** Как у категорий: если у страницы нет категорий — удаляем сразу, иначе показываем
`ConfirmDialog`. После удаления текущей страницы переходим на основную страницу `"/"`. Основную страницу удалить нельзя.

**Прочее.** После правок сервера обновить `openapi/Adashboard.Server.json` и перегенерировать клиент (две сборки —
порядок описан в `AGENTS.md`). Обновить `AGENTS.md`: заменить терминологию «раскладка» на «страница», отразить
маршруты `/api/pages`, модель со свойством `Path`, несколько страниц и переименованные компоненты/сервисы.

## Критерии приёмки

- [ ] `dotnet build` всего решения проходит без ошибок; `openapi/Adashboard.Server.json` обновлён, клиент
      `IDashboardApi` перегенерирован с методами страниц.
- [ ] В коде и UI не осталось доменных «раскладок»: модели/сущности/сервис/контроллер/компоненты и логи названы
      «страница»/`Page`; каркасные Blazor `DefaultLayout`/`MainLayout` не тронуты.
- [ ] Новая init-миграция создаёт схему со свойством `Path` у страницы и уникальным индексом; БД создаётся с
      основной страницей (пустой путь) и стартовым наполнением.
- [ ] `GET /api/pages` отдаёт список страниц, `GET /api/pages/{id}` — страницу с категориями и карточками;
      `POST /api/pages`, `PUT /api/pages/info`, `DELETE /api/pages/{id}` работают; маршруты `/api/layout*` отсутствуют.
- [ ] Создание страницы с пустым/занятым/некорректным путём отклоняется сервером с понятной ошибкой;
      основную страницу (пустой путь) удалить нельзя.
- [ ] Удаление страницы с категориями удаляет и их, и карточки; после удаления текущей страницы происходит переход на `"/"`.
- [ ] Клиент: адреса `"/"` и `"/{path}"` открывают нужные страницы; несуществующий путь показывает понятную ошибку.
- [ ] В шапке есть кнопка «Добавить страницу» рядом с кнопкой редактирования (в режиме редактирования);
      «Настройки сайта» остались в шапке.
- [ ] На странице отдельным блоком есть текстовые кнопки «Добавить категорию», «Настройки страницы»,
      «Удалить страницу»; удаление недоступно для основной страницы.
- [ ] В диалоге страницы при создании slug генерируется из русского названия (транслитерация) и перестаёт
      генерироваться после ручного ввода пути или при редактировании.
- [ ] В диалоге категории есть селектор страницы; перенос категории на другую страницу сохраняется и
      отражается в UI.
- [ ] Тексты в UI, комментарии и логи — на русском; `AGENTS.md` обновлён.
