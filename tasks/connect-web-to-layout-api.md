# Связать фронтенд `Adashboard.Web` с API раскладки

## Цель
Приложение `Adashboard.Web` должно получать раскладку из `Adashboard.Api` при загрузке (`GET /api/layout`) и сохранять её в API при завершении редактирования (`PUT /api/layout`). После того как связка заработает, удалить захардкоженную раскладку из фронтенда.

## Требования
- **Рабочая область:** все изменения только в `Adashboard.Web` (SvelteKit, TypeScript, adapter-node, npm). Проекты `Adashboard.Api` и легаси `Adashboard` (Blazor) не изменяются: контракт API (`GET`/`PUT /api/layout`) уже реализован и достаточен.
- **Доступ к API:** в `vite.config.ts` добавить dev-прокси: путь `/api` проксируется на `http://localhost:5024`. Благодаря прокси запросы идут на тот же origin, поэтому CORS в API не настраивается. Фронт обращается к API по относительным путям (`/api/layout`).
- **Слой маппинга:** добавить отдельный модуль (например, `src/lib/dashboard/api.ts`), который:
  - описывает «сырые» типы ответа API;
  - преобразует ответ API в модель фронтенда и обратно при сохранении. Форматы различаются:
    - категория в API хранит `position: { order, width }`, во фронте — плоские `order`, `width`;
    - карточка в API хранит `position: { order }`, во фронте — плоский `order`;
    - `statusMode` в API — число (`None = 0`, `Reachable = 1`, `NoServerError = 2`, `Success = 3`), во фронте — строковый union (`'none' | 'reachable' | 'noServerError' | 'success'`);
    - категория в API содержит `dashboardLayoutId`, карточка — `categoryId` (при сохранении заполнять их из контекста);
  - предоставляет функции загрузки (`GET /api/layout`) и сохранения (`PUT /api/layout`) раскладки.
- **Загрузка при старте:** стор инициализируется пустой раскладкой (без сида). При монтировании страницы раскладка запрашивается из API и записывается в стор; на время запроса показывается состояние загрузки. Загрузка выполняется на клиенте (в `onMount`), без SSR-загрузки и без реализации `load`.
- **Сохранение:** при выключении режима редактирования (кнопка завершения редактирования) отправлять всю раскладку целиком одним `PUT /api/layout`. Успешный ответ — `204 No Content`. Сохранять всю раскладку: настройки сайта (тема, заголовок, описание, логотип, интервал), категории и карточки.
- **Обработка ошибок:** при ошибке загрузки показать понятное пользователю сообщение и продолжить работу с пустой раскладкой; при ошибке сохранения показать сообщение, не теряя правки в памяти. Интерфейс не должен падать. Реализация сообщений — средствами существующего UI/стилей, без добавления новых зависимостей (например, простое уведомление/баннер).
- **Удаление сида:** после того как связка работает, удалить файл `src/lib/dashboard/seed.ts` и все ссылки на `createSeedLayout` из кода.
- **Комментарии:** оставлять подробные обучающие комментарии на русском языке в соответствии с правилами проекта для `Adashboard.Web`.
- **Зависимости:** новые npm-пакеты не добавлять.

## Критерии приёмки
- [ ] В `vite.config.ts` настроен прокси `/api` → `http://localhost:5024`.
- [ ] Есть модуль маппинга: он корректно переводит формат API ↔ модель фронта, включая `position`/`order`/`width` и числовой ↔ строковый `statusMode`.
- [ ] При запущенных `Adashboard.Api` и `Adashboard.Web` раскладка на странице берётся из API (совпадает с данными из базы), а не из фронтенд-сида.
- [ ] Изменения (карточки, категории, настройки, перетаскивание) сохраняются в базе при выходе из режима редактирования.
- [ ] После перезагрузки страницы сохранённые изменения отображаются (данные приходят из API).
- [ ] При остановленном API страница показывает понятное сообщение об ошибке и пустую раскладку, без падения.
- [ ] Файл `src/lib/dashboard/seed.ts` удалён, ссылок на `createSeedLayout` и захардкоженную раскладку в коде не осталось.
- [ ] `npm run check` завершается без ошибок.
- [ ] `npm run build` завершается без ошибок.
